# EdgeTune Windows：交给 Agent 的实机测试说明

仓库：https://github.com/shitao462/EdgeTune-Windows  
文档日期：2026-10-12  
主要目标：在 LOL 无边框窗口模式下，不切换界面即可呼出浮窗、控制音乐和查看双语歌词。

## 1. 直接发给 Windows Agent 的任务

将仓库克隆到 Windows 后，把下面这段话发送给能访问该电脑和仓库的 Agent：

> 请读取仓库的 `docs/WINDOWS_AGENT_TEST_PLAN.md`，按文档完成 EdgeTune Windows 实机测试。先记录环境与当前提交，再编译、运行并逐项测试。优先验证网易云音乐、QQ 音乐，以及 LOL 无边框窗口模式中的呼出、切歌与不抢焦点。测试时可切换歌曲、暂停和恢复、调整 EdgeTune 设置并重启 EdgeTune。发现问题后定位并修复源码，再执行相关复测和核心回归检查。将测试报告与必要截图保存到 `test-results`；每项写明通过、失败或未测试，附证据。缺少播放器、游戏环境或需要我登录、重启、修改系统设置时，明确告诉我需要做什么；不要把未测试项目写成通过。请保留现有工作和用户设置，不要关闭系统防护或修改游戏文件。完成后给出报告路径、修改摘要和仍需我验证的项目。暂不推送修改或发布版本，等我确认。

Agent 若只能运行命令、不能操作桌面，应自动完成构建与代码测试，并把需要用户手动执行的界面检查列出来。不要用源码推断替代实机结果。

## 2. 当前已知情况

- Mac 上已经编译 Windows 目标成功，跨平台歌词回归检查通过。
- 首次 GitHub Windows 自动构建成功，并生成了 x64 便携包。
- 尚未在用户 Windows 电脑验证 UI、播放器会话、音量动画或 LOL 内覆盖效果。
- Windows 版是 C# / .NET 10 / WPF；最低目标 Windows 10 2004（19041），软件包为 x64。
- 媒体识别依赖播放器发布 Windows 系统媒体会话（SMTC）。客户端版本不支持时，需要记录具体版本和会话信息，不能声称该播放器已完整支持。
- LOL **无边框窗口模式**是必须验证的主要场景；独占全屏是兼容性探索，不保证覆盖。
- 玻璃背景可能回退为半透明外观。若只有半透明、没有背景模糊，要明确记录为回退，不写成“原生玻璃已通过”。

## 3. 准备与环境记录

先检查是否已有未提交修改；记录并保留，不要直接重置仓库。

记录以下信息到报告：

| 项目 | 要记录的内容 |
| --- | --- |
| 系统 | Windows 版本、内部版本号、x64 / ARM64 |
| 机器 | CPU、显卡型号和驱动版本 |
| 屏幕 | 数量、分辨率、各屏缩放、主屏、排列方向 |
| 游戏 | LOL 版本、窗口模式、分辨率 |
| 播放器 | 网易云 / QQ / Spotify / Apple Music 的版本与安装来源 |
| 音频 | 输出设备、是否使用蓝牙或 USB 耳机 |
| EdgeTune | 提交 SHA、构建时间、EXE 路径、快捷键 |
| Agent | 是否可操作桌面、是否可获取窗口和前台进程信息 |

可在 PowerShell 中执行：

```powershell
git status --short
git rev-parse HEAD
Get-ComputerInfo | Select-Object WindowsProductName, WindowsVersion, OsBuildNumber, OsArchitecture
Get-CimInstance Win32_VideoController | Select-Object Name, DriverVersion
Get-Process EdgeTune -ErrorAction SilentlyContinue | Select-Object Id, Path
```

请准备网易云和 QQ 客户端及已登录账号；账号登录由用户完成。Spotify / Apple Music 未安装或无可用账号时标记为未测试。LOL 测试使用训练模式或自定义房间，避免影响正常对局。

## 4. 获取软件或构建源码

### 方案 A：只运行软件，不安装开发环境

1. 打开仓库 Actions → Build Windows，选择与待测提交对应的成功运行。
2. 登录 GitHub 后下载 `EdgeTune-Windows-x64`。
3. 解压下载文件，再解压其中的软件 ZIP。
4. 保留整个目录，放到固定位置，例如 `C:\Apps\EdgeTune`，运行 `EdgeTune.exe`。
5. 构建产物保留 30 天；过期时在 Actions 使用 Run workflow 重新构建，或走方案 B。

### 方案 B：用于 Agent 定位和修复

需要 Git 和 .NET 10 SDK。若没有 SDK，请先告诉用户；不要误装只有 Runtime 的版本。

```powershell
git clone https://github.com/shitao462/EdgeTune-Windows.git
Set-Location EdgeTune-Windows
dotnet --info
dotnet run --project tests/EdgeTune.Tests.csproj -c Release
dotnet build src/EdgeTune.Windows/EdgeTune.Windows.csproj -c Release
dotnet publish src/EdgeTune.Windows/EdgeTune.Windows.csproj -c Release -r win-x64 --self-contained true -o artifacts/EdgeTune-Windows-x64
Start-Process .\artifacts\EdgeTune-Windows-x64\EdgeTune.exe
```

已经克隆时不要再覆盖同名目录。构建 / 替换软件前，通过托盘退出待测 EdgeTune；仅停止确认属于待测版本的进程。新版本仍使用同一个固定软件路径。若开机启动指向别处，记录并在用户同意后更新。

**构建验收：** 歌词测试通过，构建与发布成功；出现警告要记录。构建成功不等于界面或游戏测试通过。

## 5. 测试顺序与判定

建议顺序：启动 → 网易云 → QQ → 双语歌词 → 音频动画 → LOL → 设置 / 主题 → 多屏 / 缩放 → 更新回归。

### A. 启动、浮窗和快捷键

| ID | 操作 | 预期 |
| --- | --- | --- |
| A01 | 启动一次，再启动第二次 | 只有一个 EdgeTune 实例和托盘图标，不出现两个浮窗 |
| A02 | 不移动鼠标到边缘 | 收起后只留下窄主题条，无大块透明区域挡住桌面操作 |
| A03 | 鼠标停留在边缘条上 | 约 0.2 秒后平滑展开，窗口约 316 × 110 逻辑像素 |
| A04 | 鼠标移出浮窗 | 约 1 秒后平滑收起，无明显闪烁或跳变 |
| A05 | 连续呼出 / 收起十次 | Ctrl+Alt+M 可重复使用，窗口不消失、不跑出屏幕 |
| A06 | 点击图钉，移开鼠标；取消图钉 | 常驻时保持展开；取消后恢复自动收起 |
| A07 | 拖动歌名上下移动并重启 | 垂直位置可调整和保存，不被动画拉回原位 |
| A08 | 用托盘打开设置、呼出、退出 | 各入口有效，退出后没有残留进程 |
| A09 | 换一个快捷键，重启，再换回 | 新快捷键生效并保存，旧快捷键释放 |
| A10 | 在可控测试程序占用快捷键后启动 | 明确提示冲突，可从托盘进入设置更换；不永久占用他人快捷键 |

特别检查：展开过程中内容不溢出正在变化的窗口边界；收起后点击边缘条外的桌面不会被 EdgeTune 截获。

### B. 音乐识别与控制

分别对网易云、QQ 执行全部测试；其他两款能安装使用时也执行。

| ID | 操作 | 预期 |
| --- | --- | --- |
| B01 | 设置选择播放器，播放歌曲 | 显示正确歌名、歌手和播放器；没有对应会话时显示等待状态 |
| B02 | 点击暂停和恢复，各三次 | 只控制所选播放器，状态与实际一致 |
| B03 | 点击上一首 / 下一首 | 曲目正确变化，歌词更新，没有上一首歌词残留 |
| B04 | 在播放器中拖动进度至开头、中间、结尾 | 歌词随实际位置调整，无持续累积偏移 |
| B05 | 同时打开两个播放器，改变所选播放器 | 只读取和控制设置选中的客户端 |
| B06 | 退出播放器，再启动并播放 | 自动恢复识别，不需重启 EdgeTune |
| B07 | 连续快速切歌十次 | 最终显示当前歌，旧请求结果不覆盖新歌，不崩溃 |
| B08 | 未运行所选播放器或未发布 SMTC 会话 | 显示清楚的等待状态，不控制另一款播放器 |

失败时先查看设置页的媒体状态，以及 Windows 音量媒体面板是否有该播放器。记录 `SourceAppUserModelId` 与进程名；不要用全局媒体键“修复”成控制任意播放器。

### C. 歌词、中文翻译和版本匹配

测试曲目由用户选择并记录歌名、歌手、专辑、时长；至少包含：中文歌、在客户端有中文翻译的外文歌、长歌词、明确纯音乐、无歌词歌曲，以及同名不同版本歌曲。

| ID | 操作 | 预期 |
| --- | --- | --- |
| C01 | 网易云播放有双语歌词的外文歌 | 使用网易云歌词；原文与中文时间对应，各一行 |
| C02 | QQ 播放有双语歌词的外文歌 | 使用 QQ 歌词；接口无翻译时保持原文，不编造翻译 |
| C03 | 对照播放器歌词与浮窗，在三个进度位置截图 | 顺序与时间一致；正常网络下目标为大部分歌词切换误差 ≤ 1 秒，超出时记录实际误差 |
| C04 | 长原文、有翻译及无翻译三种情况 | 不碰到设置键；无翻译最多两行，有翻译各一行，长句合理截断且工具提示可读 |
| C05 | 快速从双语歌切换到中文歌或纯音乐 | 旧翻译清除，不残留上一首文字 |
| C06 | 播放明确纯音乐、无歌词、接口失败的曲目 | 只有明确纯音乐显示“纯音乐，请欣赏”；其他情况显示查找中或暂无歌词 |
| C07 | 播放现场版、翻唱、重制版或同名歌曲 | 不因只匹配歌名而使用其他版本的歌词 |
| C08 | 测试网络不可用，再恢复 | 请求有超时、应用不冻结；恢复后切到其他歌再切回可重新查询 |
| C09 | 主歌词源不可用但 LRCLIB 有匹配 | 回退歌词可显示；不能将备用歌词报告为原播放器来源 |

主源 / 回退来源可用临时诊断日志或请求记录确认，但不要把完整歌词、账号 Cookie 或令牌写入日志和报告。测试结束移除临时诊断，或保留为默认关闭的选项。

### D. 实时音频动画（每次修复后必须复测）

| ID | 操作 | 预期 |
| --- | --- | --- |
| D01 | 播放有明显强弱变化的音乐，观察 30 秒 | 边缘条连续随所选播放器实际音量变化，不只是固定周期动画 |
| D02 | 观察最长和最短状态 | 底端稳定，仅上半部分伸缩，最长时仍为圆角 |
| D03 | 暂停、恢复、关闭 / 开启动画 | 暂停或关闭后静态，恢复后重新跳动 |
| D04 | 所选播放器静音 / 暂停，保持 LOL 或其他应用有声音 | 不跟随游戏或其他应用声音；静音下系统峰值行为需记录，暂停必须恢复静态 |
| D05 | 两款播放器同时播放，切换所选播放器 | 峰值来源跟随选择，不能读取整个系统混音 |
| D06 | 切换扬声器 / 耳机 / 蓝牙输出 | 设备连接完成后目标 10 秒内恢复，不需重新启动 |
| D07 | 重启播放器、EdgeTune；最后更新构建再启动 | 动画继续可用，不要求录屏授权，不遗留无效音频会话 |

失败时记录音频输出设备、播放器进程及 Windows 音频会话情况。需要时只记录数值峰值区间；不要录制音频。

### E. LOL：最高优先级

进入训练模式或自定义房间。先把 LOL 设为无边框窗口，记录分辨率和快捷键。测试时确认游戏聊天框未获得输入焦点。

| ID | 操作 | 预期 |
| --- | --- | --- |
| E01 | 游戏中按呼出快捷键 | 浮窗出现在游戏上方，不需要 Alt+Tab；连续十次有效 |
| E02 | 呼出后观察游戏前台窗口与焦点 | 游戏仍前台，鼠标与键盘操作继续有效 |
| E03 | 点击浮窗的暂停、恢复、上一首、下一首 | 音乐控制成功；游戏不最小化、不切到桌面，点击后游戏继续响应 |
| E04 | 不点击，只查看双语歌词 | 歌词正常更新，音乐动画继续运行 |
| E05 | 移开鼠标并继续操作游戏 | 浮窗自动收起；边缘之外不挡住点击 |
| E06 | 开启图钉常驻，进行 5 分钟训练 | 浮窗保持可见、不闪烁，不持续抢焦点；关闭图钉恢复收起 |
| E07 | 游戏 Alt+Tab、切回，以及更改无边框分辨率 | 浮窗恢复正确置顶和位置，不丢失快捷键 |
| E08 | 游戏音量较大、音乐暂停，再恢复 | 边缘条只根据所选音乐源变化 |
| E09 | 观察游戏性能和 EdgeTune 资源占用 | 没有明显卡顿或输入延迟；记录空闲、动画和游戏中的 CPU / 内存 |
| E10 | 用户愿意时尝试独占全屏 | 单独记录结果；无法覆盖是已知兼容限制，不写成无边框通过 |

焦点证据：优先记录呼出前、呼出后、点击切歌后的前台窗口所属进程；若 Agent 无此能力，由用户实际确认游戏是否继续响应并在报告注明“人工确认”。

**必须报告为未满足主要目标的情况：** 无边框下无法呼出、必须切桌面才能操作、切歌导致游戏失焦 / 最小化、透明区域阻挡游戏点击。

若 Vanguard 或游戏弹出兼容性提示，记录提示与触发步骤并停止该场景；不要关闭防护、绕过反作弊或向游戏注入代码来通过测试。

### F. 设置、主题和保存

| ID | 操作 | 预期 |
| --- | --- | --- |
| F01 | 逐一选择 5 个纯色和 3 个渐变 | 原文、装饰条与收起边缘同步更新，渐变可见 |
| F02 | 在黑色、白色、玻璃间切换 | 文字、按钮和翻译可读，无白底白字等问题；玻璃回退需单独记录 |
| F03 | 改播放器、颜色、背景、图钉、动画、快捷键后退出重启 | 设置均保存，浮窗位置保留 |
| F04 | 打开 / 关闭设置多次 | 只有一个设置窗口，关闭设置不会退出主应用 |
| F05 | 启用登录自启，用户确认后注销 / 登录 | 自动启动一份正确路径的 EdgeTune；注册表仅修改当前用户 EdgeTune 项 |
| F06 | 关闭自启，再次登录 | 不自动启动；按用户希望恢复测试前设置 |

注销、重启、系统缩放或默认音频设备调整，应先让用户保存其他工作并确认，再操作。测试过程中保存好原设置，结束后按用户偏好恢复。

### G. 多屏、缩放及边界情况

- 分别在 100%、150%、200% 缩放验证字体清晰、尺寸和边缘命中区域；无法覆盖的配置标记未测试。
- 两块屏幕不同缩放，鼠标置于各屏并按快捷键，浮窗应在对应屏幕内右侧呼出。
- 副屏在主屏左侧或上方（负坐标），验证浮窗不会跑到屏外。
- 拔掉副屏、改变分辨率、锁屏再解锁，浮窗应可恢复。
- 测试任务栏不同位置和自动隐藏；浮窗应位于可用工作区。
- 连续运行至少 15 分钟，观察错误日志和资源增长；初次验证不宣称长时间稳定性已通过。

## 6. 修复后的核心回归门槛

每次修改，无论修什么，至少复测：

1. 歌词自动测试、构建和发布均成功。
2. 网易云 / QQ 当前可用的播放器仍能识别、暂停恢复和切歌。
3. 有翻译与无翻译各一首，歌词更新和按钮间距正常。
4. 实时音频动画、暂停恢复、仅上半部分伸缩与圆角正常。
5. 快捷键呼出、自动隐藏与图钉常驻正常。
6. LOL 无边框呼出与切歌不抢焦点（缺少游戏环境则明确未测试）。
7. 退出旧版 → 替换到固定路径 → 启动新版，设置保留，以上功能仍有效。

不要为了测试通过，把依赖实际音量的动画替换为假动画、把所选播放器控制替换成任意播放器控制，或删除失败的测试。
